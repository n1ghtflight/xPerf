# XPerf — Flight Performance & Route Planner for FS2024 · handoff

Written 2026-10-16, updated 2026-10-19. Read this first, then the code.

## What it is

A web app that plans a flight for Microsoft Flight Simulator 2024 from **aircraft + departure + arrival**:
cruise level optimisation, climb/descent profile, TOC/TOD, fuel, non-GPS navigation (VOR/NDB/DME,
US Victor/Jet airways, FAA published routes, pasted or SimBrief routes), departure/arrival briefings with SID/STAR/approach
selection and FAA plates, airliner takeoff and landing performance, live weather, terrain, charts, and a **.PLN export**
for the FS2024 world map. Free/public data only. For simulation/education only.

Two ways to run it: the owner's **local server** (`server.py`, live data, `/api`) and the **public static site**
<https://xperf.n1ghtflight.workers.dev> (packs mode: offline AIRAC packs + a METAR/TAF relay; installable PWA).

## Run

```bash
cd D:\FlightSims\XPerf
python server.py          # http://localhost:8765  (python server.py 8770 for a second/test instance)
python build_packs.py     # packs/<AIRAC>/ for packs mode and the static site
python tools/build_site.py --wx https://xperf-wx.n1ghtflight.workers.dev    # static site -> dist/site/
python tools/airac_update.py --check     # current cycle vs local packs vs live site; no flag = rebuild + deploy + verify
```

- **After any change to `server.py` / `navdata.py` the user must restart the server.** Static files (html/js) are
  served with `Cache-Control: no-cache`; script and style tags carry `?v=…` version strings — bump them on every edit.
- First run downloads ~40 MB of FAA/OurAirports data into `cache/` (a few seconds each); later runs are instant.
- Python 3.14 stdlib only (no pip packages). Node 24 for syntax checks and the test harness.
- The user usually runs their own server on **8765**. For testing, start a separate instance on **8770**
  (`python -u server.py 8770` in the background).

## Web release (Cloudflare)

- **Site**: Worker `xperf`, assets only, serving `dist/site/`. **Relay**: Worker `xperf-wx` (`tools/wx-worker.js`,
  `ALLOW_ORIGIN = https://xperf.n1ghtflight.workers.dev`), proxies aviationweather.gov METAR/TAF with CORS.
  It also serves `/data/cache/metars.cache.csv.gz` and `/data/cache/tafs.cache.xml.gz` (the worldwide files Random flight
  uses; gzip bytes passed through, cached 5 min). An empty or non-gzip upstream body is answered 502, `no-store`, and not cached.
- **Never run `wrangler deploy` in the repo folder**: wrangler 4 without a config generates one with the current folder
  as the asset directory and publishes the whole repo. Deploy only through `tools/airac_update.py` (or its `deploy()`),
  which writes an explicit `wrangler.toml` in a temp folder and refuses if the asset directory isn't `dist/site`.
- **AIRAC**: a Claude scheduled task `xperf-airac-refresh` runs `tools/airac_update.py` Thursdays 06:00 local; it does
  nothing unless a new cycle is effective (2611 starts 2026-10-29), then rebuilds packs + site, deploys and checks the
  live `packs/current.json`. The title-bar chip shows "● AIRAC <cycle>" on the site, "● Live data" on the server.
- `_headers` caches `/packs/:cycle/*` for a year; `current.json`, html and js revalidate. The service worker's precache
  list is generated by `build_site.py`.
- Git history was rewritten on 2026-10-19 to drop the old EUROCONTROL snapshot (`apm_snapshot.json`); clones from
  before that need a fresh clone or `git reset --hard origin/main`.

## API endpoints (server.py)

`/api/airports` OurAirports (49k) · `/api/navaids` · `/api/airways` (V/J/colored) ·
`/api/airportinfo?ident&aliases&country&lat&lon` (runways, freqs, ILS, charts, SID/STAR procs, METAR/TAF + decoded TAF) ·
`/api/terrain?locs=lat,lon|…` · `/api/routes?orig&dest&olat&olon&dlat&dlon` (FAA preferred/TEC/CDR expanded to waypoints) ·
`/api/regions?pts=id,lat,lon|…` (ICAO regions for .PLN) · `/api/rwyindex` (ident → [longest land ft, longest paved ft, lit], for
Random flight) · `/api/wxbulk?kind=metars|tafs` (aviationweather.gov's worldwide gzip cache files; an empty or non-gzip
download is refused: the last good copy is served, else 502) · `/api/health`

## Data sources

- **Performance**: OpenAP (TU Delft) for 37 airliners/large jets incl. WRAP ADS-B climb/descent stats; XPerf's own table
  (`data/ga_perf.json`) for 82 GA/turboprop/bizjet types. GA fuel flow is engine power × SFC, calibrated to the published
  cruise fuel flow where the table has one. Takeoff/landing: generic transport-jet model tuned per type to manufacturer
  airport-planning charts (A20N and B738 tuned closely). EUROCONTROL data is not used or shipped.
- **Airports/navaids/runways/frequencies**: OurAirports (public domain). Free-text fields are stripped of `<>"` on load.
  Packs also hold `rwyidx.json` (ident → [longest land ft, longest paved ft, lit]) for Random flight.
- **FAA NASR 28-day CSV** (current AIRAC via `navdata.airac()`): ILS, FIX, NAV, AWY, DP, STAR, PFR, CDR.
- **FAA d-TPP** → official plate PDFs (US only). **ILS outside US**: X-Plane GPL nav.dat via OpenAP (2013, flagged).
- **Weather**: aviationweather.gov METAR/TAF (server, or the relay on the site); Open-Meteo winds/temps aloft and terrain.
- Map tiles: OpenStreetMap (CSS dark filter) + OpenTopoMap. CARTO needs an API key — don't use. Navigraph: not used (decided).

## Features (current state)

- **Start screen**: hero banner (instruction + four one-click example flights: C172 KPAO→KTRK, SR22 EGTF→LFPN,
  A320 EGLL→LFPG, B789 KJFK→EGLL) above the setup form; hidden once planned, back with New flight.
- **Random flight** (`random.js`): a button on the start banner and a Ctrl+K command open a panel in place of the setup
  form. Prompts: aircraft group (GA / airliner) and aircraft, time (day / night / any), departure and arrival weather
  (snow / rain / low visibility / any), distance (short / long / any); "Any" fills all four. It loads aviationweather.gov's
  worldwide METAR + TAF files (live weather; 5 min cache) and the runway index, screens airports for the aircraft's
  runway needs, and offers 5 flights, or labelled near misses ("the closest flights say what differs") when fewer match.
  Night flights use a lit runway; GA needs a land runway, jets a paved one (from `rwyidx.json`). Picking an
  option plans it like an example flight. An empty METAR file shows an error with Retry, never "no matches".
- **Setup form**: searchable aircraft (remembered), departure/arrival/alternate (ICAO/IATA/local/aliases), navigation
  (Direct · VOR · VOR+NDB · Airways US · Published FAA · Your route — paste or SimBrief), ETD, payload/TOW, extra fuel,
  level rules, optimise fuel/time, manual level, no-O₂ 12,500 ft limit.
- **After planning**: the form moves into the **All settings** drawer; a chip bar edits the plan in place (aircraft menu =
  search box + long list). Views in the sidebar: Overview (tiles, warnings callout, blueprint) · Route & nav log (map fills
  the window, vector SIDs labelled) · Airports & weather (list → detail) · Takeoff & landing · Profile · Fuel & levels ·
  FS2024 setup · Settings. Ctrl+K palette; `G` then a letter switches views; `E` exports the .PLN.
- **Level optimisation** (`planProfile`): every candidate level checked for ceiling, buffet, terrain along the profile,
  airway MEA and oxygen; falls back step by step with a warning instead of a hard error.
- **Navigation**: VOR/NDB Dijkstra with AIM service volumes; FAA airways router with MEA/MOCA/COP; published routes;
  imported routes (airways expanded, SID/STAR recognised, unresolved idents listed).
- **Takeoff & landing** (airliners): V1/VR/V2, flex/derate, flaps, required vs available runway; VREF/VAPP, autobrake,
  landing distance (dispatch and at arrival), with Packs/anti-ice/flap/thrust/reverse options.
- **.PLN export**: FPType/RouteType/CruisingAlt, airports with runways, waypoints with airways, ICAO regions, SID/STAR, approach.

## Testing

- Unit: `node --test tests/*.test.mjs` (127 tests).
- Numbers: `node tools/regress.mjs compare --port 8770` (6 replayed flights must be identical; `--accept` only for an
  intended change, after reading the diff).
- UI: `node tools/ui_check.mjs --mode server|packs [--only a,b]` (~50 checks, ~10 min per mode; never two runs at once).
  Checks replay recorded network fixtures (`tools/regress/fixtures/`, made by `regress.mjs record`).
- Harness diagnostics: a timed-out check names the stalled browser call, the page step (`window.__pf`), the status line
  and any request the replay interceptor still holds; `open()` fails naming any app file that didn't load; a run that
  ends mid-check prints `ABORT <check>`. A rare packs-mode stall (~1 in 40 runs, check passes on rerun) is still
  unexplained — when it recurs, those messages should name the cause.

## Conventions / gotchas

- Edit with a Python replace script written to a file, asserting each replacement matches exactly once; bash heredocs
  with backticks/backslashes broke several times. Several files are CRLF — normalise `\n` ↔ `\r\n` in the script.
- **Never call `/api/...` directly from the UI** — extend `XD` in data.js (server and packs branch).
- Syntax-check after edits: `node -e "new Function(require('fs').readFileSync('nav.js','utf8'))"`.
- Top-level `const` in a classic script is global but **not** a `window` property (`window.AcPicker` is undefined).
- `navdata.memo` uses an **RLock** (builders call other memoised builders — a plain Lock deadlocked).
- Runway ids differ between sources ("7L" vs "07L") → always compare with `rwyKey()`.
- Leaflet: keep whole zoom levels (`zoomSnap: 1`) — fractional zoom shows tile seams; draw the map only when visible.
- Edge headless on Windows: kill the process tree (`taskkill /T`) only while it is still running.
- localStorage keys: `xperf.ac`, `xperf.theme`, `xperf.data`, `xperf.tab`, `xperf.sec.N`, `xperf.winds`, `xperf.detlog`,
  `xperf.map`, `xperf.aptSel`, `xperf.blueprint`, `xperf.simbrief`, `xperf.to.opts`, `xperf.ldg.opts`, `xperf.to.side`,
  `xperf.deprwy.ICAO`, `xperf.sid.ICAO`, `xperf.star.ICAO`, `xperf.appr.ICAO`, `xperf.pub.DEP-ARR`, `xperf.random`.

## Known limits / open items

- **.PLN not yet confirmed inside FS2024** — ask the user for feedback and adjust tags if needed.
- Free official plates/procedures are **US only**; elsewhere ChartFox/SkyVector links + visual/ILS approach options.
- Published routes only exist between larger US airports; small fields fall back to airways.
- Minimums shown are the standard CAT I baseline; real DA/MDA only on the plate.
- Takeoff/landing: generic model, no obstacles or VMCG/VMCA/tyre limits; only A20N and B738 tuned closely.
- Random flight can offer military and non-ICAO fields (the runway index is keyed like the airport list); a departure with a weather
  condition needs a METAR station, so small fields without one are never picked for it.
- Forum announcement of the site: on hold (owner's call).
- Ideas not done: METAR-based runway-in-use, alternate fuel, aircraft V-speeds per weight for GA.

## User preferences seen in this chat

- Flies FS2024; wants **visual, glanceable** output, minimal scrolling, suggested defaults with the option to override,
